# YouTube Music search and artwork, 0.19

The public catalogue adapter follows the WEB_REMIX song-filter / music-shelf / continuation architecture reviewed in [Metrolist](https://github.com/MetrolistGroup/Metrolist/tree/876e355181fd3b04e7063b10442fef1b721d53b3), specifically `innertube/.../YouTube.kt` search/searchContinuation and `pages/SearchPage.kt` song parsing. The songs/videos filter values are compatible public client protocol values. VEXO remains GPL-3.0-or-later and retains its own Java playback, authorization, library and UI. This change does not import Google account cookies or pretend the public catalogue is the user's private YouTube Home feed.

MusicSearch reads video IDs from playlist data, navigation, title or overlay endpoints; extracts artist browse links and both flex/fixed-column durations; chooses the largest provided cover; rejects podcasts, greyed rows and invalid IDs. Provider continuations are kept separate from the NewPipe fallback cursor. Metadata calls use the existing bounded preview transport. Search runs on its own worker pool; stale UI generations cannot replace a newer field/query.

Artwork now uses [Glide 4.16.0](https://github.com/bumptech/glide/tree/v4.16.0) and its OkHttp integration. Requests for the same URL/size share work; bindings cancel earlier requests and use Glide's keyed request tags, preserving VEXO's source tag. Disk caching stores replaceable image data in app cache. Small cards avoid speculative 1024px/maxres requests. Original cover URLs are retried when a resized request fails. Network timeouts are 4s connect, 6s read and 8s per call, independent from music extraction. Application memory callbacks trim pooled/cached images without cancelling visible views.

IntroRecognition uses only explicit creator/extractor chapter metadata: the first chapter must start at zero and be exactly Intro, Introduction or Opening credits, followed by a 1–90-second boundary with more than 30 seconds remaining. It does not infer music onset from silence or claim fingerprint recognition. The user must enable skip intros. Stored private start points take priority. Duration mismatch, shared rooms, full-version selection and unknown metadata prevent unintended seeks.
