# VEXO cloud radio and live listening

Worker endpoint: https://vexo-music-cloud.kavindukavishka785.workers.dev . No external model API secret is shipped in the Android app. Workers AI uses the platform binding. Anonymous device sessions are short-lived signed credentials, stored encrypted in Android Keystore-backed storage. The server signing secret is held as a Cloudflare secret binding and is absent from source.

Cloud MindRadio sends only the explicitly typed music command, selected genre/language/mood/energy/artist preferences and a short continuation of the previous command after consent. It does not upload memories or listening history. The server returns bounded search phrases and exclusions; playable songs still come from the existing catalogue. AI is not allowed to invent playback URLs, lyrics or rights. Reset consent/context in Smart → Privacy. Current model: `@cf/meta/llama-3.1-8b-instruct-fp8`. A language request can be interpreted incorrectly; check the generated radio and refine it.

Limits: 5 AI requests per anonymous device/day, 100 across this service/day; 3 room creations per device/day, 20 globally/day; up to 8 members per room, 3 queued requests per member, 50 total requests, 2-hour room expiry. These application limits are deliberately small and do not upgrade any plan. Cloudflare account-wide free quotas still apply, including usage by other applications. Daily gates use SQLite-backed Durable Objects with expiry cleanup. If quotas or provider access fail, the app keeps local radio available. OAuth cannot read account billing subscriptions, so no claim is made about the user's existing billing setup; no subscription or billing method was changed here.

Rooms use a separate Durable Object per room and hibernating WebSockets. A cryptographically random invite creates room-scoped membership; a member's token is stored only encrypted on their device and as a hash on the server. Invite hashes and member hashes are not broadcast. Joining shares the chosen display name and queued track metadata with that room. Only the host can advance/pause/end. A member can add requests and remove their own requests. The host controls a per-person round-robin queue. The server never broadcasts audio or proxies music; each phone uses its own existing playback source. Local device-only tracks cannot be shared to other phones.

The foreground playback service owns the connection, periodically publishes host position/play state, resumes WebSockets with bounded backoff and corrects follower drift above 1.5 seconds. A local pause opts a follower out; users can explicitly follow again. Starting a personal queue leaves the room. This is best-effort synchronized listening, not sample-accurate audio. Device buffering, Bluetooth latency, battery restrictions and source availability can affect synchronization. On host disconnection, followers pause until it reconnects; sessions end after two hours.

SQLite storage and host credentials are automatically removed by room alarms. Ending a room closes its sockets. No contact invitations, emails or messages are sent automatically. A person with the full invite can join until expiry/member limit, so share the invite intentionally.

Tests: `node --test cloud-service/policy.test.mjs`. Live verification uses two independent authenticated WebSocket clients and a real Workers AI request; Android UI/sync policies are covered in Robolectric. Physical-device timing/background checks remain necessary.
